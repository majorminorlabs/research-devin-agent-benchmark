## Root cause

In `serialize_response`, the endpoint's return value is re-validated against `secure_cloned_response_field` — a cloned field whose model requires **aliases** for input. The buggy code only pre-converted content when `exclude_unset and isinstance(response_content, BaseModel)`, and used `response_content.dict(exclude_unset=...)` **without `by_alias`**:

- `dict()` emits **field names** (`name`), but the cloned field's alias (`aliased_name`) is what `validate_model` looks up → `MissingError` → all aliased-model responses failed validation.
- For `List[Item]`/`Dict[str, Item]`, content isn't a `BaseModel`, so pre-conversion was skipped entirely. Validation then rebuilt each item via `cls(**dict(item))` — marking every field as set — so `exclude_unset` silently did nothing on nested items.

## Fix (`fastapi/routing.py`)

Added `_prepare_response_content()`, which recursively converts `BaseModel` → `dict` with `by_alias=True` and `exclude_unset`, descending into lists and dicts so nested models keep their `__fields_set__`-aware filtering before re-validation. `serialize_response` now calls it unconditionally before `field.validate`, replacing the old ad-hoc `exclude_unset` block.
