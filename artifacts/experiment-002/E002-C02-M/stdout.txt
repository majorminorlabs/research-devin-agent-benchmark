Summary of what I found and changed:

**Root cause** — in `serialize_response` (`fastapi/routing.py`), when `response_model_exclude_unset=True` the raw return value was dumped via `response_content.dict(exclude_unset=True)` *without* `by_alias`, then re-validated against the response field:

- For a model with aliases (`Item.name` → `aliased_name`), the dict used field names, so re-validation failed `aliased_name: field required` → response validation error (issue #1043).
- For `List[Item]` / `Dict[str, Item]` return values, the `isinstance(response_content, BaseModel)` guard meant the unset-field dump never happened at all — `fields_set` was lost through re-validation, so `exclude_unset` had no effect on nested models (issue #1063).

**Fix** — mirrors upstream PR tiangolo/fastapi#1074: added `_prepare_response_content`, which recursively converts `BaseModel`s inside lists/dicts to dicts with `by_alias=True, exclude_unset=exclude_unset` *before* validation, and `serialize_response` now always calls it.
