## Diagnosis

`Location: ///i8n.example2.com/302` is a network-path reference with an extra leading slash. `urlsplit('///i8n.example2.com/302')` parses it as an **empty netloc** with path `/i8n.example2.com/302`, so `urljoin(request.url, location)` resolved it against the original host:

```
'http://www.example.com/302' + Location '///i8n.example2.com/302'
  -> 'http://www.example.com/i8n.example2.com/302'   (wrong host)
```

Browsers tolerate the extra slash and treat it as `//i8n.example2.com/302` (scheme-relative), so Scrapy should too.

## Fix

In `scrapy/downloadermiddlewares/redirect.py`, when the raw `Location` header value starts with `//`, rebuild it as `<request-scheme>://<host/path>` (stripping all leading slashes) before `urljoin`:```python
location = safe_url_string(response.headers['location'])
if response.headers['location'].startswith(b'//'):
    request_scheme = urlparse(request.url).scheme
    location = request_scheme + '://' + location.lstrip('/')

redirected_url = urljoin(request.url, location)
```

This matches upstream Scrapy's fix. `//` still yields the request scheme, `///+` now collapses to the correct host, and single-slash/absolute/relative `Location` values are untouched.
