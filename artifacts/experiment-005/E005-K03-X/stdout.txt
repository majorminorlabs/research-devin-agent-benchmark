**Root cause:** `IOLoop._ioloop_for_asyncio` was a `WeakKeyDictionary` mapping asyncio loops → IOLoop wrappers. Since each `BaseAsyncIOLoop` value holds a strong reference to its key (`self.asyncio_loop`), the weak keys could never be collected — every wrapper stayed reachable forever, and the map grew on each create/close cycle.

**Fix (matching upstream Tornado 5.0.2):**

- `tornado/ioloop.py` — `_ioloop_for_asyncio` changed from `weakref.WeakKeyDictionary()` to a plain `dict()`; removed the now-unused `import weakref`.
- `tornado/platform/asyncio.py` —
  - `BaseAsyncIOLoop.initialize`: before registering, sweep the map for asyncio loops already `is_closed()` (covers wrappers whose asyncio loop was closed via asyncio interfaces, bounding stale entries to one).
  - `BaseAsyncIOLoop.close`: `del IOLoop._ioloop_for_asyncio[self.asyncio_loop]` so Tornado-initiated closes remove the mapping immediately.
