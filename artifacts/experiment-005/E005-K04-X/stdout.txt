## Root cause

`RequestHandler.finish()` ended by eagerly clearing `self.ui` to break the handler↔ui-closure reference cycle. `WebSocketHandler` calls `finish()` during the handshake (status 101), so the cleanup fired at handshake time — too early (breaking `render_string` during the connection) and with no hook left to run at real close, the request-handler cycle cleanup never happened at the correct point in the close lifecycle.

## Changes

**`tornado/web.py`** — extracted the cycle break into an overridable method; `finish()` now calls `self._break_cycles()`. Ordinary request handling is behavior-identical:

```python
        self.on_finish()
        self._break_cycles()

    def _break_cycles(self):
        # Break up a reference cycle between this handler and the
        # _ui_module closures to allow for faster GC on CPython.
        self.ui = None
```

**`tornado/websocket.py`** — `on_connection_close` runs the cleanup after `on_close()`, and a `WebSocketHandler._break_cycles` override defers it while the connection is alive:

```python
        if not self._on_close_called:
            self._on_close_called = True
            self.on_close()
            self._break_cycles()

    def _break_cycles(self):
        # WebSocketHandlers call finish() early, but we don't want to
        # break up reference cycles (which makes it impossible to call
        # self.render_string) until after we've really closed the
        # connection (if it was established in the first place,
        # indicated by status code 101).
        if self.get_status() != 101 or self._on_close_called:
            super(WebSocketHandler, self)._break_cycles()
```
