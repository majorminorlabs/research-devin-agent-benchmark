## Root cause
Bash's integration couldn't see the live session's aliases: `get_aliases()` spawned a *new* `bash -ic alias` subprocess (which only sources bashrc — never the user's interactive aliases), and `app_alias` never exported the session's aliases to the `thefuck` process.

## The repair — `thefuck/shells/bash.py`
- **`app_alias`** now emits `alias fuck='TF_CMD=$(TF_ALIAS=fuck PYTHONIOENCODING=utf-8 TF_SHELL_ALIASES=$(alias) thefuck $(fc -ln -1)) && eval $TF_CMD'` — `$(alias)` snapshots the current shell's aliases at execution time, passed as env-prefix on the `thefuck` command *inside* the substitution.
- **`get_aliases`** reads `os.environ['TF_SHELL_ALIASES']` and parses bash's `alias name='value'` format via the existing `_parse_alias`.
- Dropped the `@cache` decorator (keyed on bashrc mtime — meaningless without the subprocess) and the now-unused `Popen`/`PIPE`/`DEVNULL`/`cache` imports.

## Key design detail
I verified empirically that the env vars **must** prefix `thefuck` inside `$(...)`. The alternative — `TF_ALIAS=fuck ... TF_SHELL_ALIASES=$(alias) TF_CMD=$(thefuck ...)` (this repo's zsh pattern) — is an assignment-only command: the vars stay shell-local and the external `thefuck` process receives *nothing* (proved via a real exec'd probe: empty env vs. full alias dump). The chosen form matches upstream's actual shipped alias verbatim (documented in nvbn/thefuck#502).
