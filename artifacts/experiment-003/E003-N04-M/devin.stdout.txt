The bug was in `Session.close()` at [session.py:34-38](file:///workspace/src/event_stream/session.py): it called `self._task.cancel()` and returned immediately. Since cancellation is delivered asynchronously, `close()` returned while the worker was still active and its `finally` cleanup hadn't run — the test showed `(True, 0)` instead of `(False, 1)`.

The fix uses the already-present `_stop` event (previously never set) for a graceful shutdown, then awaits the worker task:

```python
async def close(self) -> None:
    self._closed = True
    self._stop.set()
    if self._task is not None:
        await self._task
```
